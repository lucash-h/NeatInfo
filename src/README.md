# src/

The React 19 frontend, built by Vite into `dist/` and served by the Worker.

| File | What it holds |
|---|---|
| `main.jsx` | Entry point |
| `App.jsx` | Shell: navigation, keyboard shortcuts, share-target, service worker |
| `AppContext.jsx` | All state and every API action |
| `api.js` | The fetch wrapper, and the one place a 401 is shaped |
| `helpers.js` | Pure display logic: read time, lapse info, archive query strings, empty states |
| `tts.js` | Speech: chunking, the Web Speech engine, the server-audio engine, the player |
| `components/` | One file per surface or sheet |

## The convention that matters most

**Components never call `api()` directly.** Every action lives in
`AppContext.jsx` and goes through `guard()`, which swallows a 401 (the Gate is
already handling it), turns anything else into a toast, and returns `undefined`
rather than an unhandled rejection. An unguarded call leaves a rejection nobody
sees, on a surface that just looks broken.

There is one known exception, recorded in `../CLAUDE.md` rather than quietly
tolerated: `TtsPlayer.jsx` calls `api()` for `/listen` and passes it to the
speech engine as `fetchJson`.

## Pure logic lives in `helpers.js`, and that is not stylistic

There is no jsdom in this project, so **components cannot be tested at all**.
Anything that is a decision rather than a rendering belongs in `helpers.js` or
`tts.js`, where `../test/` can reach it. That is why "which empty message does
Archive show" and "which speech engine does this article get" are exported
functions rather than inline JSX.

When a bug turns out to live inside a component, the fix is usually to move the
decision out of it first.

## Speech, briefly

`tts.js` has two engines behind one interface — `speak / pause / resume /
cancel / available`:

- **Tier 1**, the browser's own voice. Works offline, needs no account, and is
  kept as the floor deliberately. It carries a `resume()` heartbeat because
  Chrome stops speaking after ~15 seconds of *total* speaking time, and a
  watchdog because the engine can stop dead firing neither `end` nor `error`.
- **Tier 2**, audio generated by the Worker, ~45 seconds at a time, stored
  nowhere. One reused `<audio>` element, unlocked inside the click that starts
  playback, with the next segment prefetched — all three are iOS requirements
  rather than polish. Media Session metadata is what makes the lock screen work.

The component picks between them through `chooseEngine()` and falls back to
Tier 1 whenever the server cannot help.

## Surfaces

Today, Pending, Archive and Starred. Starred is `<Archive starredOnly />`; the
favourite filter is applied server-side, because doing it client-side lied as
soon as there was more than one page.
